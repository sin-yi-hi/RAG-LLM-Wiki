## 重點
1. **定義**：RAG 是優化 LLM 輸出的過程，讓模型在生成回答之前，先參考「訓練資料以外的權威知識庫」。不需要重新訓練模型，是成本較低的做法。
2. **沒有 RAG 時 LLM 的 4 個問題** ✅：
   1. 不知道答案時給出錯誤資訊。
   2. 使用者需要最新、具體的答案時，給出過時或籠統的資訊。
   3. 根據不具權威性的來源產生回答。
   4. 不同訓練資料用同一個詞指不同東西，造成術語混淆而答錯。
3. 訓練資料是靜態的，所以 LLM 有「知識截止日」。
4. **比喻**：沒有 RAG 的 LLM 像一個「過度熱心的新員工」，什麼都很有自信地回答，但沒有跟上最新狀況。
5. **4 個好處** ✅：成本效益高、資訊即時、提升使用者信任（可附來源與引用）、開發者掌控度更高（可更換來源、依權限限制檢索、方便除錯）。
6. **運作 4 步驟** ✅：
   1. 建立外部資料：把 API、資料庫、文件等資料用 embedding 模型轉成數字（向量），存進向量資料庫。
   2. 檢索相關資訊：把使用者的問題也轉成向量，到向量資料庫做相關性搜尋。
   3. 增強 LLM 提示：把找到的資料加進使用者的提示中。
   4. 更新外部資料：定期或即時更新文件與向量，讓資料保持最新。
7. **與語意搜尋的關係**：語意搜尋可以提升 RAG 的結果；傳統關鍵字搜尋在知識密集任務上效果有限。
