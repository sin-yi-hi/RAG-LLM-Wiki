# 沒有 RAG 的 LLM 有什麼問題？

## 1. 知識有截止日
訓練資料是靜態的，模型只知道訓練當時的資訊，之後發生的事它不知道。[S2]

## 2. 會「一本正經地胡說八道」（幻覺 hallucination）
- 只靠模型權重記憶知識的模型，可能產生看似合理但錯誤的內容。[S1]
- AWS 列出 LLM 的 4 個常見問題：[S2]
  1. 不知道答案時給出錯誤資訊
  2. 給出過時或籠統的資訊
  3. 根據不具權威性的來源回答
  4. 術語混淆（同一個詞在不同地方意思不同）
- IBM 的例子：問產假可以請多久，沒有 RAG 的聊天機器人回答「想請多久就請多久」—— 這是錯的，因為各地規定不同。[S3]

## 3. 說不出答案從哪來
只靠參數記憶的模型，很難說明它的答案依據什麼。[S1]

## 4. 不知道你公司的內部資料
LLM 沒看過公司內部文件（例如人事規章、產品手冊），自然回答不出來。（整理，根據 [S2][S3] 的企業情境）

## 5. 要更新知識很貴
只靠參數的模型，要更新知識就得再訓練。[S1] 持續重新訓練的運算與金錢成本很高。[S3]

## RAG 怎麼對應這些問題（整理）
| 問題 | RAG 的對策 |
|---|---|
| 知識過時 | 查最新的外部資料 [S2] |
| 幻覺 | 根據找到的資料回答，降低幻覺 [S3][S4] |
| 說不出來源 | 可以附上出處讓人查證 [S2][S4] |
| 不懂內部資料 | 把內部文件放進知識庫 [S7] |
| 更新很貴 | 換資料不用重新訓練 [S1][S2] |
