RAG 是什麼？
讓 AI 先查資料、再回答

檢索增強生成（Retrieval-Augmented Generation）入門

本簡報內容全部來自我的「RAG LLM Wiki」，每頁下方標示 Wiki 頁面與原始來源編號 S1–S7。

開場：今天想讓大家知道，為什麼 ChatGPT 這類 AI 有時候會亂講，以及業界最常用來改善它的方法 RAG。

今天的學習目標

① 說得出來

用一句話說明 RAG 是什麼、為什麼需要它

② 畫得出來

畫出 RAG 的四個步驟：建索引 → 檢索 → 增強 → 生成

③ 判斷得出來

知道 RAG 的限制，以及什麼時候用 RAG、什麼時候不用

先讓聽眾知道今天結束後要會什麼，最後的小測驗會對應這三個目標。

先想一想：AI 這樣回答，對嗎？

我想請產假，可以請多久？
想請多久就請多久喔！😊

❌ 這是 IBM 提到的真實例子。產假規定每個國家、每個州都不一樣，AI 卻很有自信地給了錯誤答案。

📌 LLM（大型語言模型）：像 ChatGPT 這種用大量文字訓練、會寫文字的 AI。

👉 比較好的做法：說「我不確定」，或先追問你在哪裡工作。

Wiki：llm-limitations｜來源 S3
可以先問台下：你覺得 AI 為什麼會這樣回答？讓大家猜一下再翻下一頁。

沒有 RAG 的 LLM，有三個大問題

📅 知識會過期

訓練資料是靜態的，有「知識截止日」，之後的事它不知道。

🌀 會一本正經地亂講

不知道答案時，可能產生看似合理但錯誤的內容，叫做幻覺（hallucination）。

❓ 說不出依據

答案從哪裡來？模型很難說明，使用者也無法查證。

另外，它也沒看過你公司的內部文件；想更新知識，就得重新訓練，很花錢。

Wiki：llm-limitations｜來源 S1S2S3
AWS 列了 4 個常見問題，這裡為了好記整理成 3 類。

用比喻理解 RAG

📖 閉卷考 → 開書考

沒有 RAG：只能靠背下來的東西作答。
有 RAG：可以先翻書找到答案，再寫答案。

— IBM 的比喻

⚖️ 法官與書記官

法官（LLM）懂一般法律，遇到特殊案件，請書記官（RAG）去圖書館找判例。寫判決的還是法官。

— NVIDIA 的比喻

Wiki：analogies｜來源 S3S4
強調：RAG 不是取代 LLM，而是幫 LLM 找資料。

所以，RAG 是什麼？

先「檢索」，再「生成」

RAG（檢索增強生成）：讓大型語言模型在回答之前，先到外部資料庫找相關內容，再根據找到的內容回答。

🧠 參數記憶

模型自己記住的知識（存在權重裡）

📚 非參數記憶

外部資料庫，換掉就能更新知識

小故事：RAG 這個名字來自 2020 年 Patrick Lewis 等人的論文。他後來說，早知道會這麼紅，就會取個好聽一點的名字 😂

Wiki：rag-definition、history-and-name｜來源 S1S2S4
原始論文用的外部資料庫是 Wikipedia，切成 2100 萬份文件。

RAG 的四個步驟

① 建索引文件切片（切成小段），轉成向量（一串數字），存進資料庫
➜
② 檢索把問題也轉成向量，找最相似的前 K 段
➜
③ 增強把找到的片段 + 問題，組成新的提示（交給 LLM 的問題與指令）
➜
④ 生成LLM 根據資料寫答案，並附上來源

🔄 資料會變，所以知識庫要定期更新。

不同來源切法不同（AWS 4 步、Gao 綜述 3 步、IBM 2 階段），但核心都是「先找再寫」。

Wiki：rag-pipeline｜來源 S2S3S4S6
①是事前準備（離線做一次），②③④是每次有人發問時才跑。

步驟①：為什麼要切片？什麼是向量？

✂️ 切片 chunk

LLM 一次能讀的 token（模型處理文字的基本單位）數量有限，不能把所有文件塞進去，所以把長文件切成幾百個 token 以內的小片段。

例：RAG 論文把 Wikipedia 切成 100 字一段。

🔢 向量 embedding

把一段文字變成一串數字。意思相近的文字，數字也會很接近 → 可以用「距離」找出最相關的片段。

問題和片段要用同一個模型轉換。

Wiki：chunking-and-embedding｜來源 S1S2S5S6S7
可以比喻成：把一本書拆成很多張便利貼，每張便利貼都貼上一個「意思座標」。

步驟②：怎麼「找」資料？

方法原理擅長
關鍵字搜尋（BM25）比對完全相同的字錯誤代碼、專有名詞
向量搜尋比對意思是否接近換句話說、同義詞
混合搜尋兩種一起查再合併兼顧兩者

🎯 重新排序（reranking）：先多撈一些（例如 150 段），再精挑最相關的 20 段給 LLM。

Wiki：retrieval-methods｜來源 S5S7
例子：查「Error code TS-999」，向量搜尋可能找不到，關鍵字搜尋可以。

走一遍：Alice 想請半天假

我可以請半天假嗎？今年假還夠嗎？

② 檢索

查 Alice 的人事資料（剩幾天假）＋公司請假規定（能不能請半天）

③ 增強

把兩份資料和 Alice 的問題放進同一個提示

④ 生成

LLM 回答「可以 / 不行、還剩幾天」，並附上規定的連結

Wiki：rag-pipeline、use-cases｜來源 S3
對照第 3 頁的產假例子：有了 RAG，AI 回答的是「這間公司、這個人」的真實狀況。

進階：切片會「失去上下文」

😵 問題

片段寫著「公司營收比上一季成長 3%」——哪家公司？哪一季？系統看不出來。

💡 解法：情境式檢索

先讓 LLM 替每個片段加一句說明，例如「這段出自 ACME 公司 2023 年 Q2 財報」，再建索引。

做法檢索失敗率降低
加情境的向量搜尋35%
＋加情境的 BM2549%
＋重新排序67%

⚠ 這是「失敗率下降的比例」，不是準確率。

Wiki：contextual-retrieval｜來源 S5
重點：RAG 好不好，很大部分取決於「找得準不準」。

RAG 的三代演進

1️⃣ Naive RAG

索引 → 檢索 → 生成，一條直線。
像查一次字典就作答

2️⃣ Advanced RAG

檢索前改寫問題、檢索後重新排序。
先想好查什麼，查完再挑重點

3️⃣ Modular RAG

加入記憶、路由等模組，可以反覆檢索。
像樂高，依任務組裝

🆕 最新發展：代理式檢索——讓 LLM 先把複雜問題拆成多個子問題，分頭去找。

Wiki：rag-paradigms｜來源 S6S7
Naive RAG 的缺點：找不準、找不全、只查一次不夠。後兩代就是在解決這些問題。

RAG、微調、提示工程，怎麼選？

提示工程RAG微調
做法改寫指令回答前先查資料用新資料再訓練
知識更新—換資料即可要重新訓練
能附來源✗✓✗
最適合先試試看要最新、可查證改變說話風格

💡 微調＝用新資料再訓練模型。RAG 和微調不互斥，可以一起用！

Wiki：rag-vs-finetuning｜來源 S2S4S6
RAG 的缺點是多了一個檢索步驟，延遲會比較高。

換掉資料庫，就能更新知識？

RAG 原始論文實驗：問 82 位在 2016–2018 年間換人的世界領袖「誰是某某職位？」

70% / 68%

索引年份對 → 答對

12% / 4%

索引年份錯 → 幾乎答錯

但 RAG 也有限制

  • 找錯資料 → 就會答錯；找到資料也可能還是幻覺
  • 模型不知道自己不知道
  • 知識庫小於 20 萬 tokens（約 500 頁）時，直接整份放進提示就好
Wiki：limitations-and-when-not｜來源 S1S3S5S6
這頁同時講 RAG 的強項（更新知識不用重新訓練）和弱點。

怎麼知道 RAG 做得好不好？

上下文相關性

找到的資料跟問題有關嗎？

答案忠實度

答案有忠於資料、沒亂編嗎？

答案相關性

有直接回答問題嗎？

還要測 4 種能力：抗雜訊、拒答（沒資料就不要硬答）、資訊整合、反事實穩健性。

Wiki：evaluation｜來源 S6
這份簡報本身也用了「答案忠實度」的概念：每頁內容都要能在 Wiki 找到出處。

RAG 用在哪裡？

👩‍💼 人資 / 客服

查公司規定、內部客服機器人

🏥 醫療

連到醫學索引，協助醫師與護理師

📈 金融

連到市場資料的分析助理

共通點：需要「最新」、「專屬」、「能查證」的資訊。

Q1. RAG 的四個步驟依序是？

建索引 → 檢索 → 增強 → 生成

Q2. 公司規章改了，用 RAG 的聊天機器人需要重新訓練嗎？

不用，更新知識庫裡的文件就好

Q3. 一份很短的社團規章（遠小於 20 萬 tokens），一定要用 RAG 嗎？

不一定，知識庫很小時可以直接整份放進提示

總結：三句話帶走

1️⃣ RAG = 先查資料，再根據資料回答，能減少幻覺、附上來源、不用重新訓練就能更新知識。

2️⃣ 四步驟：建索引 → 檢索 → 增強 → 生成，其中「找得準不準」最關鍵。

3️⃣ RAG 不是萬靈丹：找錯就答錯；知識庫很小時不一定需要。
